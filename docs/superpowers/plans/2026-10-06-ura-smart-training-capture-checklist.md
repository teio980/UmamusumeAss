## 已有代码直接复用，不要求重新采集

- 日期、心情、目标与倒计时：继续使用旧 CareerScreenObserver、解析器和状态结果。
- 体力：继续使用原能量条视觉检测。
- 数字：复用技能流程数字解析，以及倒计时的裁剪、放大和 Tesseract 回退代码；倒计时保持 4 倍，训练数值校准后使用 2 倍。
- 五项按钮、凸起选中状态、返回及动作完成检测：使用已有模板和检测逻辑。原流程在同一帧比较五项图标高度，CenterY 最小的就是选中项；五项共用这个规则，不新增逐项选中模板，也不要求逐项选中截图。
- 合宿、Lv1/Lv5、友情训练参考：先用仓库现有截图；训练等级和彩圈不作为本版独立识别字段。

训练增益和失败率是旧固定/比例策略没有实际比较的数据。它们仅新增读取区域与调用，识别引擎和数字处理共用原代码；这些新字段仍需要实际识别验证。

## 程序先验证和自动留证

开发阶段先使用已有截图运行真实 Windows OCR / Tesseract，再列具体缺口。运行时若某训练类型核心字段未知或双帧不一致，程序自动保存已采集的 PNG 和 recognition.json，不要求用户手工配对双帧或填写 CSV。

保存位置：`%LOCALAPPDATA%/UmamusumeAss/debug/hachimi/career/smart-training-*/<训练类型>/`。每次运行每种类型最多保存首次异常；将程序日志列出的对应目录提供给开发者即可。没有帧可保存时仍通过现有日志报告。

## 直接沿用原流程，不要求先补选中素材

| 读取内容 | 实现 / 验证方式 |
|---|---|
| 当前选中项 | 同帧比较五项旧图标匹配位置，最高项即选中；测试覆盖五种最高项 |
| 六项收益 | 共用固定属性栏位置和同一个数字读取器；不按选中训练类型分别建识别器 |
| 失败率 | 以最高项图标的横向中心定位气泡，共用同一数字读取器；现有 Temp 图覆盖耐力和非零值 |
| 实际运行出现识别异常 | 先用程序自动保存的双帧与 JSON 修正；只有自动留证不足时才指出具体补图需求 |

不要求刻意凑到 5%/6%，数值边界由测试验证。缺少某种选中状态的独立截图，不构成实现前置条件或用户采集任务。真实设备五项扫描与完整育成由运行日志继续验收。

取消必交：高低体力两套、主界面、人工双帧配对、Lv1～Lv5、六月下半月、支援身份、羁绊颜色、Hint、封顶、其他分辨率专项、视频和 CSV。当前正常运行日志用于后续设备与完整育成验收。

## 后续确有异常需补图时

使用当前 Global 英文客户端的原始 ADB / 模拟器完整 PNG，保留当前分辨率，不裁剪、不标数字、不压缩。只点击未凸起选中的训练项目进行切换，等待收益稳定后截一张；不要再次点击已选中的项目，以免执行训练。无需为了补图进行危险训练。
